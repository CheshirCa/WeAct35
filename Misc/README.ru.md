# CDC ACM для Orange Pi RV2

В использованном для WeAct35 ядре Orange Pi RV2 Ubuntu 24.04.5 LTS `6.6.63-ky` выключен `CONFIG_USB_ACM`. Поэтому FS35 и FS096 могут быть видны в `lsusb`, но не получать `/dev/ttyACM*`.

Был исследован community external module из [Tolcen/ttyACM-driver-for-OrangepiRV2](https://github.com/Tolcen/ttyACM-driver-for-OrangepiRV2), commit `a78a0f46aaf9a82fb44cf135c808f3c5f7057625`. Вручную собранный для точной пары kernel/riscv64 модуль `cdc-acm.ko` имеет SHA-256 `2f1501a5d038e1c082ee8f7f0281430c9e15fc201ad52b71375ba2c83e6e08ef`; он был вручную загружен и использован на зафиксированной RV2.

SPDX-маркеры исходников указывают GPL-семейство, но не снимают риски provenance и соблюдения условий распространения. Получайте и проверяйте upstream самостоятельно.

Модуль не является частью libweact, не входит в Debian-пакеты WeAct35, не настраивается на автозагрузку и не является универсальным модулем Linux. Он относится только к зафиксированной среде RV2/riscv64 с `6.6.63-ky`; другие kernel builds не поддержаны. Внешний модуль может taint-ить kernel и привести к сбою системы.

## Ручное использование под контролем владельца

После самостоятельного получения совпадающих source/module проверьте kernel и digest до загрузки:

```sh
uname -r
sha256sum cdc-acm.ko
sudo insmod ./cdc-acm.ko
ls -l /dev/ttyACM*
```

Не настраивайте по этой инструкции autoload и не копируйте модуль в системный каталог. После ручной загрузки используйте `weact-list --verbose` до любой записи. Дайте пользователю доступ через группу `dialout` с повторным входом в сессию; не используйте `chmod 777` для tty. Если проверка владельца через `/proc` неокончательна для уже подтверждённого дисплея, `--allow-unknown-occupancy` — узкое разрешение; оно не принимает занятый или неверный порт.
